The Rule Evaluation API evaluates one or more rule definitions against a single image. It returns an overall score and
match decision for each definition, along with the score produced by every prompt.

Evaluation does not store the image or create an asset. Supply definitions in the request; they do not need to exist
in the server's global `rule-definitions` configuration.

```http
POST /rule-evaluations
```

The endpoint must be [enabled in configuration](../configuration-reference.md#api). When it is disabled, the route is
not registered and returns `404 Not Found`.

## Request Definitions

URL, S3, and multipart requests use the same definition structure:

```json
{
  "definitions": [
    {
      "name": "logo",
      "prompts": [
        "a green tree logo",
        "a photograph of a mountain"
      ],
      "threshold": 0.7
    }
  ]
}
```

| Field Name                | Type   | Description                                                 | Required | Constraints                         |
|---------------------------|--------|-------------------------------------------------------------|----------|-------------------------------------|
| `definitions`             | Array  | Rule definitions to evaluate against the supplied image.    | Yes      | 1-10 definitions                    |
| `definitions[].name`      | String | Name used to identify the definition in the response.       | Yes      | Non-blank; maximum 32 characters    |
| `definitions[].prompts`   | Array  | Visual descriptions compared with the image.                | Yes      | 1-100 distinct, non-blank strings   |
| `definitions[].threshold` | Number | Minimum overall score required for the definition to match. | Yes      | From `0.0` through `1.0`, inclusive |

Each prompt can contain up to 256 characters. Names and prompts are normalized to lowercase; prompts are also trimmed.

## Evaluate an Image From a URL

Send an `application/json` request and include the image URL in `source.http.url`:

```http
POST /rule-evaluations HTTP/1.1
Content-Type: application/json

{
  "source": {
    "http": {
      "url": "https://konifer.io/img/konifer-small.png"
    }
  },
  "definitions": [
    {
      "name": "logo",
      "prompts": [
        "a green tree logo",
        "a photograph of a mountain"
      ],
      "threshold": 0.7
    }
  ]
}
```

| Field Name        | Type   | Description                                | Required |
|-------------------|--------|--------------------------------------------|----------|
| `source.http.url` | String | URL of the image to download and evaluate. | Yes      |

The URL host must be present in `source.url.allowed-domains`, and the downloaded content cannot exceed
`source.url.max-bytes`. See the [Source configuration](../configuration-reference.md#source).

### Example

Allow `konifer.io` in `source.url.allowed-domains`, or replace the example URL with an image on an allowed host.
The deprecated top-level `url` field remains a fallback when `source.http.url` is absent.

<Tabs groupId="konifer-example-language" defaultValue="curl">
<TabItem value="curl" label="curl">

```bash
curl --fail-with-body \
  --request POST \
  'http://localhost:8080/rule-evaluations' \
  --header 'Content-Type: application/json' \
  --data '{
  "source": {
    "http": {
      "url": "https://konifer.io/img/konifer-small.png"
    }
  },
  "definitions": [
    {
      "name": "logo",
      "prompts": [
        "a green tree logo",
        "a photograph of a mountain"
      ],
      "threshold": 0.7
    }
  ]
}'
```

</TabItem>
<TabItem value="kotlin" label="Kotlin (suspending)">


## Evaluate an Uploaded Image

Send a `multipart/form-data` request with exactly one `metadata` part and one `asset` part. Do not include `url` in the
metadata.

| Part Name  | Content-Type                                | Purpose                                  | Required |
|------------|---------------------------------------------|------------------------------------------|----------|
| `metadata` | `application/json`                          | JSON containing the `definitions` array. | Yes      |
| `asset`    | Image MIME type (for example, `image/jpeg`) | Raw image content to evaluate.           | Yes      |

### Example

Evaluate the local Konifer logo against two descriptions. Scores depend on the image and configured model;
a successful request does not require the rule to match.
Run the curl upload from this documentation repository, or replace `static/img/konifer-small.png` with your own PNG.

<Tabs groupId="konifer-example-language" defaultValue="curl">
<TabItem value="curl" label="curl">

```bash
curl --fail-with-body \
  --request POST \
  'http://localhost:8080/rule-evaluations' \
  --form 'metadata={"definitions":[{"name":"logo","prompts":["a green tree logo","a photograph of a mountain"],"threshold":0.7}]};type=application/json' \
  --form 'asset=@static/img/konifer-small.png;type=image/png'
```

</TabItem>
<TabItem value="kotlin" label="Kotlin (suspending)">

```kotlin
val definition = RuleDefinitionRequest(
  name = "logo",
  prompts = listOf("a green tree logo", "a photograph of a mountain"),
  threshold = 0.7,
)
client.ruleEvaluation()
  .fromBytes(Files.readAllBytes(Path.of("static/img/konifer-small.png")), ImageFormat.PNG)
  .withDefinition(definition)
  .evaluate()
  .valueOrThrow()
```

</TabItem>
<TabItem value="java" label="Java (blocking)">

```java
var definition = new RuleDefinitionRequest(
  "logo", List.of("a green tree logo", "a photograph of a mountain"), 0.7);
var evaluation = client.ruleEvaluation()
  .fromBytes(Files.readAllBytes(Path.of("static/img/konifer-small.png")), ImageFormat.PNG)
  .withDefinition(definition)
  .evaluate();
```

</TabItem>
</Tabs>

Uploaded content cannot exceed `source.multipart.max-bytes`.

## Evaluate Multiple Definitions

Evaluate several definitions against the same image in one request. Konifer embeds the image once and returns an
independent result for each definition. Here, the logo and photograph definitions each have their own prompts and
threshold; matching one does not prevent the other from matching.

<Tabs groupId="konifer-example-language" defaultValue="curl">
<TabItem value="curl" label="curl">

```bash
curl --fail-with-body \
  --request POST \
  'http://localhost:8080/rule-evaluations' \
  --form 'metadata={
  "definitions": [
    {
      "name": "logo",
      "prompts": [
        "a green tree logo",
        "a company logo"
      ],
      "threshold": 0.7
    },
    {
      "name": "photograph",
      "prompts": [
        "a photograph of a mountain",
        "a photograph of a person"
      ],
      "threshold": 0.7
    }
  ]
};type=application/json' \
  --form 'asset=@static/img/konifer-small.png;type=image/png'
```

</TabItem>
<TabItem value="kotlin" label="Kotlin (suspending)">

```kotlin
val definitions = listOf(
```

## Response

A successful evaluation returns `200 OK`. This illustrative response uses the single-definition logo request above;
actual scores depend on the image and configured model.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "results": [
    {
      "name": "logo",
      "threshold": 0.7,
      "score": 0.84,
      "matched": true,
      "promptScores": [
        {
          "prompt": "a green tree logo",
          "score": 0.84
        },
        {
          "prompt": "a photograph of a mountain",
          "score": 0.61
        }
      ]
    }
  ]
}
```

| Field Name                        | Type    | Description                                              |
|-----------------------------------|---------|----------------------------------------------------------|
| `results`                         | Array   | Evaluation result for each supplied definition.          |
| `results[].name`                  | String  | Normalized name of the evaluated definition.             |
| `results[].threshold`             | Number  | Threshold supplied for the definition.                   |
| `results[].score`                 | Number  | Highest score from the definition's prompts.             |
| `results[].matched`               | Boolean | Whether `score` is greater than or equal to `threshold`. |
| `results[].promptScores`          | Array   | Score for each normalized prompt in the definition.      |
| `results[].promptScores[].prompt` | String  | Prompt that was scored.                                  |
| `results[].promptScores[].score`  | Number  | Score produced for that prompt.                          |

### Reading the Results

For each definition, `score` is the highest value in `promptScores`. The `matched` field is `true` when that score
is greater than or equal to `threshold`. A `matched: false` result is a successful evaluation, not a request failure.
Each prompt score is reported so you can tune wording and thresholds against representative images.

These are model scores, not confidence percentages. See
[Tuning a Rule Definition](../../concepts/rule-evaluation.md#tuning-a-rule-definition) for guidance.

## Error Responses

| Status                       | Cause                                                                                  |
|------------------------------|----------------------------------------------------------------------------------------|
| `400 Bad Request`            | The request, rule definitions, URL, multipart parts, image format, or size is invalid. |
| `404 Not Found`              | The Rule Evaluation API is disabled.                                                   |
| `415 Unsupported Media Type` | The request is not `application/json` or `multipart/form-data`.                        |

Evaluation accepts the same [supported image formats](../../concepts/Assets/overview.md#content) as asset storage.
