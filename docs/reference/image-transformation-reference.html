Image Transformation

Use transformations to resize, crop, convert, or adjust an image. Supply the parameters below when you:

  • Request an on-demand variant through the Fetch Asset API
  • Define a variant profile
  • Preprocess an upload
  • Configure eager variant generation

Image Resizing​

The h, w, and fit parameters determine the output dimensions and whether Konifer scales, crops, or distorts the source image.

The resizing examples use this 1365×1024-pixel cow photo. Download it to try the same transformations with your own Konifer instance. The examples on this page are saved outputs from the Konifer API.

fit (Default)​

Requirements: h or w (or both).

Konifer scales the image to fit within the requested dimensions while preserving its aspect ratio.

  • With only w, Konifer calculates the height from the source aspect ratio.
  • With only h, Konifer calculates the width from the source aspect ratio.
  • With both, the output fits inside the requested bounding box. Neither dimension exceeds its requested value, and no cropping occurs.

fill​

Requirements: Both h and w are required.

Konifer scales the image until it covers the requested dimensions, preserving its aspect ratio, then crops any overflow. The output matches the requested width and height.

Use g to choose which part of the scaled image remains. The default, center, removes an equal amount from opposite sides when possible.

stretch​

Requirements: Both h and w are required.

Konifer scales the image to the requested width and height without preserving its aspect ratio.

warning

The output may appear squashed or stretched when the requested aspect ratio differs from the source.

crop​

Requirements: Both h and w are required.

Konifer removes pixels from the source to produce the requested width and height. Unlike fill, crop does not scale the image before cropping. Use g to choose which part of the source remains.

All four requests below use w=320&h=320&format=webp. Compare how much of the pasture remains and whether the cow keeps its proportions. The outlined frames mark the same 320×320 target box; the empty space around the fit result belongs to this page, not the returned image. Select a caption to inspect the output at its native size.

For example, after uploading the photo at /documentation/cow, request the filled square with:

GET /assets/documentation/cow/-/content?format=webp&w=320&h=320&fit=fill

Gravity Options (g)​

Both fill and crop support these gravity values:

  • center (default): Keeps the geometric center of the image.
  • entropy: Keeps the area with the most detail, measured through contrast and edges. It often works well for landscapes, products, and textured objects.
  • attention: Keeps the area that the saliency model identifies as visually important, including faces and human features. It often works well for profile pictures and social content.

Image Formats & Quality​

Konifer can return variants in these formats:

  • JPEG
  • PNG
  • WEBP (single and multi-page)
  • AVIF
  • JPEG XL
  • HEIC
  • GIF (single and multi-page)

Quality (q)​

The q parameter controls compression for lossy formats. Lower values reduce file size and discard more image detail. Higher values preserve more detail and require more storage and network bandwidth.

FormatDefault QualityNotes
JPEG80Good balance for photos.
WEBP80Generally 30% smaller than JPEG at equivalent quality.
AVIF50Superior compression, but computationally expensive to encode.
PNGN/APNG is lossless. The q parameter is ignored.
JPEG XL90High-efficiency modern standard.
HEIC50Standard for iOS captures.
GIF100Images are generally small due to a limited color palette.

Defaults are based on the Sharp library recommendations.

tip

Higher quality settings can increase encoding time. AVIF encoding is especially sensitive to this setting.

Both versions of this cheetah photo use w=640&format=webp. Compare the fur around the eyes: q=10 loses fine detail in exchange for a smaller file. Open each output at its native 640×427 size to inspect the difference. These file sizes apply to this photo and these settings.

Color Space​

The cs parameter controls the output color space and its available color gamut.

  • origin (default): Retains the embedded ICC profile, when present, without converting the color space.
  • grayscale: Converts the image to a single-channel (or 2-channel if alpha exists) grayscale image. This is more space-efficient than the grayscale filter; however, color-adding transformations (such as pad-c) will also be flattened to grayscale.
  • srgb: Converts the image to sRGB using its embedded ICC profile. Konifer removes the profile from the output because most displays assume sRGB by default.
  • p3: Converts the image to the Display P3 profile, the standard for modern iOS-based cameras and wide-gamut displays.
note

Converting an sRGB or grayscale source to P3 does not create colors absent from the source. The conversion may increase file size without changing its appearance.

Geometry & Effects​

Rotate (r)​

Use r to rotate the image clockwise in 90-degree increments.

These small outputs use the same bird photo with w=160&h=160&format=webp. Each image fits inside the same square frame. Follow the bird and its branch as the photo turns clockwise; 90° and 270° produce portrait images.

If auto is supplied, Konifer reads the EXIF Orientation metadata from the original variant and rotates the image accordingly. The resulting transformed variant has the EXIF Orientation tag stripped to prevent double-rotation by displays.

Flip (f)​

Use f to mirror the image along an axis:

  • v: Vertical flip (top-to-bottom).
  • h: Horizontal flip (left-to-right).

These examples use the same bird photo with w=240&format=webp. With f=h, the bird faces the opposite direction. With f=v, the top and bottom exchange places while the bird stays on the same side of the image.

Filter (filter)​

Use filter to apply one of these effects:

  • none (default): No filter applied.
  • black_white: Applies a binary threshold so each pixel becomes pure black or pure white.
  • grayscale: Removes color while preserving shades of gray.
  • sepia: Applies a warm, brownish tone matrix (identical to the CSS sepia(100%) filter).

Each example below uses the same flamingo photo with w=480&format=webp. Compare the solid black and white regions from black_white with the tonal detail retained by grayscale.

note

The grayscale filter is different from the grayscale color space (cs). Images with this filter applied will still be 3-channel (or 4-channel if the image contains alpha). Other transformations, such as padding, will still retain color.

For example: ?filter=grayscale&pad=10&pad-c=%23FF2900 produces a grayscale image with a red border. Encode # as %23 in a URL.

Blur (blur)​

Use blur to apply a Gaussian blur. Higher values soften more detail. Konifer applies blur after resizing, so compare values at the dimensions you plan to deliver.

Range: 0 (no blur) to 150 (heavy blur).

Borders & Padding​

Use pad to extend each edge of the image canvas by a number of pixels.

Amount (pad)​

Set the number of pixels added to each edge.

Padding Color (pad-c)​

Set the padded area's color with a CSS-style hex value in pad-c.

  • If pad-c is omitted: Padding is transparent for PNG, WebP, AVIF, JPEG XL, and HEIC. It is white for JPEG and GIF
  • Hex Format: Supports both RGB (Opaque) and RGBA (Transparent) formats.

Examples​

  • Solid Red: pad-c=%23FF0000 (URL encoded #FF0000)
  • Translucent Red (50% Opacity): pad-c=%23FF000080 (URL encoded #FF000080)

Both requests below resize the squirrel to 320×213 pixels, then add pad=16 on every edge. The final canvas measures 352×245 pixels. With WebP, omitting pad-c leaves the added area transparent; the checkerboard is this page's background.

GET /assets/documentation/squirrel/-/content?format=webp&w=320&pad=16&pad-c=%23FF2900

Metadata​

Strip Metadata​

Use strip to remove EXIF, XMP, or IPTC metadata from the output.

tip

Add strip to a variant profile, eager variant, or preprocessing rule when every matching asset needs the same metadata policy. Stripping metadata during preprocessing removes it from the original variant and every variant derived from it.
