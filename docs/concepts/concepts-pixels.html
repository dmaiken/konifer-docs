Raw Pixels

Request format=pixels to get the transformed image as raw pixel samples. You can use these samples in image processing, computer vision, or machine learning code that needs a pixel buffer instead of a compressed image file.

Konifer returns application/octet-stream content with a .bin extension. The body contains packed, unsigned 8-bit samples (uint8, values 0–255), with no image header, dimensions, or embedded metadata. Konifer returns the first frame of an animated source. The quality parameter has no effect on pixel output.

Channel order and layout​

Use pixel-channels to choose the channels and their order. The default is RGB. You can specify any permutation of RGB or RGBA, such as BGR, BGRA, or ARGB, or use GRAY for one grayscale channel. Input is case-insensitive; each color channel must appear once.

Use pixel-layout to choose how Konifer arranges the samples in the buffer:

LayoutExample for three RGB pixelsBuffer shape
interleaved (default)R1 G1 B1 R2 G2 B2 R3 G3 B3Height × width × channels (HWC)
planarR1 R2 R3 G1 G2 G3 B1 B2 B3Channels × height × width (CHW)

Pixels follow row order, from left to right and then top to bottom. In planar layout, each plane contains one complete channel in that row order. The order of the planes follows pixel-channels.

For gray, Konifer returns one channel and reports interleaved layout even if you request planar. Both layouts would contain the same bytes for a single channel.

Color and transparency​

Color pixel output requires sRGB or Display P3. Use color-space=srgb or color-space=p3 to convert a source with another color space; the default color-space=origin retains the source color space and can fail for grayscale, CMYK, or other sources containing uncommon ICC profiles.

For pixel-channels=gray, Konifer converts the output to grayscale. You can omit color-space, use color-space=origin, or use color-space=grayscale. Combining gray with color-space=srgb or color-space=p3 returns 400 Bad Request.

Include A to retain source transparency. Konifer adds an opaque alpha sample if the source has no alpha channel. Color output without A drops the alpha channel. For gray, Konifer composites transparency against white before returning grayscale samples.

Fetch bytes with their attributes​

Fetch content with the desired transformation to get the bytes and their attributes in one response. Konifer puts dimensions and pixel attributes in K-Attr-* HTTP headers, so you can interpret the buffer without a separate link request.

curl --fail-with-body \
  --dump-header profile-picture.headers \
  --output profile-picture.bin \
  'http://localhost:8080/assets/users/123/profile-picture/-/content?format=pixels&width=224&height=224&fit=fill&color-space=srgb&pixel-channels=BGR&pixel-layout=planar'

The response headers include:

K-Attr-Width: 224
K-Attr-Height: 224
K-Attr-Format: pixels
K-Attr-Rotate: 0
K-Attr-Horizontal-Flip: false
K-Attr-Color-Space: srgb
K-Attr-Pixels-Channels: bgr
K-Attr-Pixels-Layout: planar
K-Attr-Pixels-Data-Type: uint8

With the client, fetchContent().valueOrThrow() returns an AssetContent whose bytes contain the buffer and whose attributes contain these decoded values. fetchAndWriteContentTo() returns AssetContentMetadata after streaming the bytes to your destination. Metadata fields can be null; they are unavailable with ContentDelivery.FOLLOW_REDIRECT. Use fetchLink() for attributes if you need an external delivery URL.

The body size in bytes is width × height × channel count: three for RGB permutations, four for RGBA permutations, or one for gray. This example produces 150,528 bytes. Use the returned dimensions because resizing, rotation, and padding can change them. See the Fetch Assets reference for curl, Kotlin, and Java examples.

The orientation attributes describe the clockwise rotation still needed for display, followed by a horizontal flip. If you need pixels with orientation applied, request rotate=auto; normalized output reports rotation 0 and flip false. See Content attribute headers for the full mapping.

Pixel variants and preprocessing​

You can combine pixel output with resizing, cropping, rotation, filters, and other image transformations. Define the same parameters in a variant profile to reuse the transformation or generate an eager pixel variant.

Konifer caches pixel variants in the object store. Channel order and layout distinguish cached variants; for example, RGB interleaved and BGR planar are separate variants. For grayscale, Konifer normalizes both layout requests to the same interleaved variant. See Variant Caching.

You can also convert an uploaded image to pixels during preprocessing:

paths {
  "/vision/**" {
    transform {
      preprocessing {
        enabled = true
        format = pixels
        color-space = srgb
        pixel-channels = RGB
        pixel-layout = planar
      }
    }
  }
}

Konifer stores this pixel buffer as the Original Variant, together with the attributes needed to decode it. You can resize it, reorder its channels, change its layout, or request an encoded format such as PNG in later variants. Preprocessing to pixels keeps one frame and 8-bit samples; preprocessing without A also discards source alpha.

Raw pixels are an output format. Upload an encoded image, such as PNG or JPEG, even when preprocessing will convert it to pixels. Konifer does not accept a raw .bin buffer through multipart, HTTP URL, or S3 source ingestion.
